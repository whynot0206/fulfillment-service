# 支付 Outbox 租约与受控死信重驱（R05）

本页描述实现与操作边界，不是已完成的故障/多实例验收报告。部署结果以本轮独立证据为准。

## 兼容升级

新增迁移为 `microservices/sql/migration-v2-outbox-lease-redrive.sql`，可重复执行：增加 `lease_owner`、`lease_until`、`redrive_count` 和运维审计表，保留原有事件、状态值、支付与事件同事务写入及唯一业务键。不要重跑旧种子、删除旧数据或改变 bootstrap 指纹。

必须先停止全部旧 Order 发布器，再迁移和部署新二进制；旧版本只按状态回写，不能与新版本混跑并声称租约隔离生效。新发布器每次领取生成独立 token，数据库时钟分配 60 秒租约；完成和失败回写均要求同 token、处理中状态、租约仍有效。旧 owner 的晚到结果仅记录租约丢失，不能重新排队或覆盖新 owner/已发送状态。新租约到期后恢复，旧版无租约的处理中记录按一分钟陈旧阈值恢复。

没有续租；下游默认读取超时为 3 秒，但进程暂停等因素仍可令调用跨越租约。此时允许重复投递，依赖 Inventory 原有幂等确认，不能解释为 exactly-once。自动失败最多 10 次进入死信；退避保持 2、4…256 秒的既有序列。

## 单条死信重驱

入口仅为 `scripts/acceptance/redrive-outbox.ps1`，没有消费者或服务 HTTP 重驱接口。只允许 `common.ps1` 校验标签归属的专用 Compose 容器、已完成的隔离初始化实例；不连接外部或已有 Windows MySQL。先在同一 PowerShell 进程加载 `use-secrets.ps1`，凭证不写入参数、SQL 或输出。

先确认故障原因已处理，并只读核验目标事件、重驱计数及订单。命令必须给出明确事件号、预期死信状态 `3`、预期重驱计数、操作者和原因。例如，已核验事件号为 `42`、重驱计数为 `0` 时：

```powershell
& ./scripts/acceptance/use-secrets.ps1
# 默认只读预览，不写事件或审计
& ./scripts/acceptance/redrive-outbox.ps1 -EventId 42 -ExpectedStatus 3 `
    -ExpectedRedriveCount 0 -Actor 'local-operator' -Reason '依赖已恢复，核对支付事实后重驱'
# 只有明确决定重驱这一个事件时，才在相同参数后增加 -Execute
```

执行阶段在一个本地事务内锁定事件和订单，校验事件类型/业务键/JSON 订单号一致，订单已支付且有外部交易号和支付时间，事件仍为预期代次的无租约死信；然后 CAS 排入同一个事件，增加重驱计数并记录审计。已发送、处理中、未支付、载荷不匹配或旧代次都拒绝。不会创建第二个事件、重新支付或直接修改库存。

原失败次数、错误、退避时间、更新时间、代次以及操作者/原因保存在 `order_outbox_redrive_audit`；事件原错误保留到后续成功或新失败。重驱不删除证据。审计插入和重新排队一同提交，审计唯一请求号/事件代次防止重复记录。请求超时或客户端错误时结果可能未知，先按输出的 requestId 核对审计，不自动重试，也不要盲目增加预期代次。

`changed=1` 只证明重新排队与审计已提交，不证明库存确认完成；另行有界等待事件发送、库存锁转确认及库存守恒。5 秒数据库锁等待和 60 秒 Docker 客户端等待只是操作超时，不是业务完成时限。失败后仍保留死信或可恢复事件，不自动改库存兜底。

## 验证边界

- `test-outbox-redrive-contract.ps1` 是无外部依赖的 SQL 构造契约测试，不触碰 Docker 或数据库。
- Java 发布器测试验证 token 传递及丢租约后不做无条件回写；仓储测试验证 CAS 条件和受影响行数处理，不能替代真实锁竞争。
- 本机已验证默认退避至 10 次失败 DEAD、错误代数拒绝、有效重驱及审计、重复重驱与已发送拒绝，并核对最终库存确认；另有确认提交后发布器崩溃、等待 60 秒租约后恢复的证据。见 [闭环补验](../../docs/closure-acceptance-2026-09-26.md)，不是多实例并发或所有非法历史数据均已覆盖。
- 真实 MySQL 应另验：A 租约过期 → 恢复 → B 领取 → A 成功/失败回写均为 0 行 → B 完成 → 任何旧回写仍为 0 行；重驱应覆盖有效死信、重复意图、已发送、未支付和错误载荷。
- 自动恢复不会修复人工篡改的事件、未知 schema 或业务事实不一致；此类情形应阻塞验收并人工排查，而不是跳过校验。
